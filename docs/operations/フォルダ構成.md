# フォルダ構成

本プロジェクトでは、コード・設定・テストを管理する「開発リポジトリ」と、ユーザーの戦績やデータベースを保持する「実データ領域」が明確に分離されています。

---

## 1. 開発リポジトリ構成（Git管理対象）

リポジトリ内の主要なフォルダ構成とその役割です。

```
ikaring-archive/
├── .github/
│   └── workflows/          # GitHub Actions CIワークフロー (tests.yml)
├── config/                 # 設定・定義ファイル (query-catalog.snapshot.json 等)
├── docs/                   # プロジェクトドキュメント
│   ├── design/             # 設計文書
│   ├── operations/         # 運用手順、使い方、SQL例、構成案内
│   ├── research/           # 一次資料調査、ダウンロードされた調査用アセット
│   └── verification/       # テストおよび整合性検証記録
├── scripts/                # 起動および環境検査スクリプト (start.py, start.sh)
├── sql/                    # データベーススキーマおよびビュー定義 (schema.sql)
├── src/                    # アプリケーションソースコード
│   ├── node/               # Node.js側実装 (クエリ抽出、認証、nxapi連携、通信ブリッジ)
│   └── python/             # Python側実装 (ikarchive: ストア、コレクター、プランナー、排他制御)
├── tests/                  # 自動テスト群
│   ├── fixtures/
│   │   └── public/         # 公開サンプルに基づくテスト用フィクスチャ
│   ├── integration/        # 結合テスト (relay.test.mjs)
│   └── unit/               # 単体テスト (test_archive.py)
├── archive.py              # メインCLIエントリーポイント
├── Start.bat               # Windows用起動バッチスクリプト
├── Start.command           # macOS用起動スクリプト
├── package.json            # Node.js依存関係定義
└── package-lock.json       # Node.js依存バージョン固定ファイル
```

---

## 2. 実データ領域構成（開発環境外・Git管理対象外）

取得した戦績データ、SQLiteデータベース、ログ、認証情報などは開発リポジトリ内には保存されず、分離された実データ領域に出力されます。

- **既定の保存先**: `~/Documents/イカリング3アーカイブ`
- **親ディレクトリの変更**: 環境変数 `IKARING_ARCHIVE_DATA_DIR` で指定可能
- **データベースパスの個別変更**: 各CLIコマンドの `--db <PATH>` オプションで指定可能

実データ領域の内部構成は以下の通りです。

```
~/Documents/イカリング3アーカイブ/
├── database/               # メインSQLiteデータベース (archive.sqlite3) およびWALファイル
├── spool/                  # 取得処理中の中間ファイル・未コミットデータの一時保管領域
├── backups/                # archive.py backup により作成されるオンラインバックアップ
├── exports/                # archive.py export により出力されるJSONおよびメディアファイル
├── logs/                   # 定期収集・LaunchAgent等の実行ログ (service.log, service-errors.log)
├── catalog/                # 最新クエリ定義マニフェスト等のキャッシュ
└── imports/                # archive.py import で取り込む外部ダンプデータの配置先
```

---

## 3. 実装・配置に関する注意事項

- **開発領域と実データ領域の分離**:
  Gitリポジトリ内に個人データ、試合結果、トークン等の秘密情報が混入しないよう、設計段階からパスを分離しています。
- **実データディレクトリの生成タイミング**:
  実データ領域内のサブフォルダ群（`database`, `logs`, `backups`, `exports` 等）は、初期状態のリポジトリに含まれているものではなく、各コマンド（`init`, `sync`, `install-service`, `backup`, `export` 等）が実行された際に必要に応じて順次作成されます。未実行の機能のディレクトリが最初から存在するわけではありません。
- **認証情報の保存先**:
  ニンテンドーアカウントの認証トークン等はnxapiの標準保存先（OSごとの安全なユーザーデータディレクトリ）または環境変数 `NXAPI_DATA_PATH` で指定された場所に保持され、リポジトリ内には一切保存されません。
